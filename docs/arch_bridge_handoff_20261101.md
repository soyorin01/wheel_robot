# arch-v6：取消离桥到转弯之间的额外等待

问题：`BRIDGE_SETTLE_SECONDS=0` 仍先检查更严格的姿态条件，可能以 0.10m/s
等待到 2.5 秒超时；随后 `TURN_WAIT_MIN_SECONDS=2.2` 又强制直行，不允许弯口确认。
这些分支请求低速或直行，不是明确的固定零速停车，实车表现可能像停顿。

改动仅在 `shiwai_arch.py`：

- `TURN_WAIT_MIN_SECONDS` 从 2.2 改为 0，取消固定时间门槛。
- `_bridge_settle_ready()`：额外确认时长为 0 时直接检查 IMU/odom 新鲜度与有效航向，
  不再进入更严格的姿态等待。`BridgeTraversal` 自己的回平、角速度、时间、里程判定原样保留。
- `_bridge_settle_command()`：传感器缺失时立即输出零，不经过速度限幅保留旧前进量。
- 版本 `arch-v6`。弯口位置阈值和连续三帧确认保留；没有近端弯口时仍保持航向前行，
  不是刚离桥就盲目右转。断线、fault、人行道停车与终点停车策略不改。

验证：5 项离桥衔接测试，17 项弯道断线测试，14 项原有回归。包括 done 立即交接、
未离桥不提前交接、传感器过期停车、近端弯口无需等待 2.2 秒、远处弯口不能提前触发。
只运行离线测试与安装路径校验，不启动机器人。实际顿挫改善需用户实车验证。
