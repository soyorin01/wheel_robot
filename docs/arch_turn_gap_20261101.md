视频 `shiwai_arch_20261101_141255.avi` 第 144 帧附近，连续弯沿断成两段。旧代码选中左下短段后，位置误差突然转负，随后输出左转；当时仍为 TURN，尚未出弯。

## 实现

1. 保留 OpenCV 连通域检测，在连通块图上做受约束 BFS。仅在已入弯、未出弯、未启用末段 ARCH 检测时使用；桥上与隧道检测不参与。
2. 从当前近端边线出发，候选远段须位于上一帧可信边沿附近，满足断口长度、两端切线和泡沫厚度相容性。最多关联三个片段；存在多个可接续分支时拒绝猜测。
3. 当前实测片段一起拟合；缺口不画成白色、不当成实测点，历史点不混入当前拟合。被关联的两块不会又被当作左右两条边线。关联期间速度目标上限 0.14m/s。
4. 当边线支持骤减、身份改变、丢线或位置误差跳变时，降低置信度并标记 `GAP suspect`。旧的高置信短段不能直接控制转向，也不能据此确认出弯。
5. 控制层最多以 0.10m/s 保持上一条可靠且符合弯道方向的转向；0.35 秒、0.04 米、传感器过期三者任一触发即停车。摄像头无新帧也检查预算；停车后不会仅因传感器恢复就重新启动预算。
6. 连续三帧恢复足够实测支持且估计稳定后恢复循迹，重置误差微分历史。完整、连续观测确实需要反向纠偏时仍可恢复左转，并非永久禁止左转。

关键参数在 `shiwai_arch.py` 的 `TURN_GAP_*` 常量；录像增加 `GAP clear/joined/suspect`、`links` 与 `GAP HOLD/GAP STOP`。二值化录像、无窗口、启动就绪检查和末段丢线保护保留。未修改终点判定。

## 验证与局限

- 新增 9 项测试：录像断口回放、仅实测点参与、不接错误远段、丢线不清保护、时间/里程/传感器停止、无新帧不延长预算、连续恢复、允许真实反向纠偏、阶段隔离及 LF 换行。测试在电脑和香橙派通过，不初始化 ROS 或发送命令。
- 原 14 项离线回归检查覆盖启动、桥状态机、隧道限速、二值化录像、配对和其他视觉行为。弯道新增一行 GAP HUD，图像比对只排除此文字区域。
- 从用户视频重建的白色掩码中，第 144 帧旧误差约 `-0.114`；修复后约 `+0.436`，仍要求右转。后续缺口超过约束，进入保护并停车，离线输出未出现原来的左转。
- 回放来自已有标注录像，不是原始相机图像；保存帧率为 15fps，控制回放按该间隔模拟。上述结果用于验证失效机制，不能证明真实闭环行驶一定过弯或完赛。修复改变轨迹后，后续实际视野也会改变。
- 编码、实际帧率、物理刹车距离、最终完赛仍需现场试跑确认。没有启动机器人测试，也没有烧录下位机。

## 启动

源码和 `ros2 run` 安装副本同步后，原命令可用；应显示 `arch-v4 (turn-gap guard)`：

```bash
cd ~/wheel_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run wheel_robot shiwai_arch.py --ros-args \
  --params-file src/wheel_robot/config/shiwai.yaml \
  -p enable_motion:=true
```

若以后从分支重新检出源码，需 `colcon build --packages-select wheel_robot` 更新安装副本。测试和 Git 提交过程不会执行上述启动命令。
