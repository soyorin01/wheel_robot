脚本：`src/wheel_robot/scripts/rush.py`（已加入 `CMakeLists.txt` 的 `install(PROGRAMS)`）

## 1. 启动（两个终端，和现在一样）

**终端 A —— 先起底盘：**
```bash
ros2 launch wheel_robot base.launch.py
```

**终端 B —— 再起速通程序（就这一条）：**
```bash
source /opt/ros/humble/setup.bash && source ~/wheel_robot/install/setup.bash
ros2 run wheel_robot rush.py --ros-args \
  --params-file ~/wheel_robot/src/wheel_robot/config/shiwai.yaml \
  -p enable_motion:=true
```

不想发车、只想看识别（车轮不动，安全）：把最后一段换成 `-p enable_motion:=false`。

节点名故意沿用 `shiwai`，这样现有的 `shiwai.yaml` 才会被套用；
脚本顶部的 RUSH 段参数会覆盖 yaml。

### 改参数后怎么生效（已配好，不用管）

`ros2 run` 执行的是 **`install/wheel_robot/lib/wheel_robot/rush.py`**，不是 `src` 里那份。
这个工作空间 **不是 symlink-install**（`AMENT_CMAKE_SYMLINK_INSTALL:BOOL=OFF`），
所以默认情况下**只改 `src` 不生效**——实车踩过：`RUSH_TURN_MIN_DISTANCE` 从 0.00
改到 4.00，起转点还是 0.22~0.31 m 一动不动。

**现在已经配好了：`install` 里的 `rush.py` 是一个软链接，指向 `src` 里那份。**

```
install/wheel_robot/lib/wheel_robot/rush.py
    -> /home/orangepi/wheel_robot/src/wheel_robot/scripts/rush.py
```

**所以你只要改 `src/wheel_robot/scripts/rush.py`，下次启动就是新参数，不用编译。**
启动时会打两行确认：

```
>>> [RUSH] 参数自检：install 里是软链接 → 改 src 立即生效 OK（/home/orangepi/.../rush.py）
>>> [RUSH] 入弯触发：visual，离桥后至少 4.00 m 且视觉确认才起转
```

**只对 `rush.py` 做了软链接，其它文件（尤其王赛的 `shiwai.py` / `shiwai_arch.py`）
一个字节都没动**——他的 `install` 和 `src` 本来就不一致，所以没用
`colcon build --symlink-install`（那会把整个包都换成软链接，等于悄悄改掉他跑的版本）。

#### 万一软链接被覆盖了

跑过 `colcon build` 之后，软链接会被覆盖成普通文件拷贝，改 src 又会不生效。
**跑一下就修回来：**

```bash
~/wheel_robot/rush_symlink.sh
```

不用记也行——启动自检会立刻报警：

```
>>> [RUSH] ⚠⚠⚠ 参数没生效！ros2 run 跑的是 install 里的旧文件，改 src 不 build 不变
>>> [RUSH]    RUSH_TURN_MIN_DISTANCE：src 里是 4.00，实际生效的是 0.20 ← 用的是这个
>>> [RUSH]    修：cd ~/wheel_robot && colcon build --packages-select wheel_robot，或直接改 install/...
```

**看到 `⚠⚠⚠` 就说明修改没生效。**

## 2. 流程顺序

```
摆正车 → 启动 → 起步巡线对齐(约1~2帧)
  → 全速直冲 0.60 m/s（w=0，固件自己保航向）
  → 单边桥（沿用原工程那套视觉+IMU 状态机，速度 0.60）
  → 桥后直冲
  → ★写死右转弯 v=0.60 w=-2.43（左轮 1.10 / 右轮 0.10）
  → ★出弯立即停车，静止满 5.0 秒（不看斑马线）
  → 巡线对齐 → 下蹲 0.16
  → ★全速盲冲隧道 2.6 秒
  → 起身直冲 → 认终点字 → 拱入 1.6 秒 → 停车 → 自动退出
```

终端里 `★` 开头的行就是阶段切换点，看日志就能知道车走到哪一步。

### 转弯怎么调（改哪里 + 每个值对应什么）

**改这两行**（`rush.py` 第 650、651 行，`RUSH 速通现场调参` 段里）：

```python
RUSH_TURN_LEFT  = 0.85   # 转弯时左轮速度 m/s
RUSH_TURN_RIGHT = 0.35   # 转弯时右轮速度 m/s
```

改完保存、重启程序即可（不用重新编译）。程序会自动算出 `v`、`w`、转弯半径，
并在**启动时打印**，同时做红线自检：

```
>>> [RUSH] 转弯参数：左轮 +0.850 / 右轮 +0.350 m/s → v=0.600 w=-1.214，半径 0.49 m，转 90° 约 1.29s
>>> [RUSH] 转弯红线自检：左+右 = 1.200 <= 1.20、单轮 <= 1.218，未被夹住 OK
```

#### 两条硬约束（超了就不是你写的值了）

1. **左轮 + 右轮 ≤ 1.20** —— 因为 `v=(左+右)/2` 不能超过遥控上限 0.60。
2. **单个轮子 ≤ 1.218** —— 遥控单轮上限。

约束 1 成立时约束 2 自动满足。**超了程序会打 `⚠` 告警**并告诉你实际会被夹成多少，
所以填错了不会翻车，但也不是你想要的转弯。

#### 换算关系

```
前进速度 v = (左轮 + 右轮) / 2      ← 车整体往前冲多快
角速度   w = (右轮 - 左轮) / 0.4118 ← 转多急
转弯半径   = 0.4118 × (左+右) / (2 × (左-右))
转 90° 耗时 ≈ 1.5708 × 转弯半径 / v
```

两数**之和的一半**决定冲多快，两数**之差**决定转多急。

#### 全范围对照表（右转：左轮必须比右轮快）

| 左轮 | 右轮 | 前进 v | 角速度 w | 转弯半径 | 转 90° | 说明 |
|---|---|---|---|---|---|---|
| 1.10 | 0.10 | 0.60 | -2.43 | 0.25 m | 0.65 s | 旧默认。**实测被压成 0.14 m 原地打转** |
| 1.05 | 0.15 | 0.60 | -2.19 | 0.27 m | 0.72 s | 还是偏急 |
| 1.00 | 0.20 | 0.60 | -1.94 | 0.31 m | 0.81 s | |
| 0.95 | 0.25 | 0.60 | -1.70 | 0.35 m | 0.92 s | |
| 0.90 | 0.30 | 0.60 | -1.46 | 0.41 m | 1.08 s | |
| **0.85** | **0.35** | **0.60** | **-1.21** | **0.49 m** | **1.29 s** | **当前默认，对齐赛道半径** |
| 0.80 | 0.40 | 0.60 | -0.97 | 0.62 m | 1.62 s | 转得偏缓 |
| 0.75 | 0.45 | 0.60 | -0.73 | 0.82 m | 2.16 s | |
| 0.70 | 0.50 | 0.60 | -0.49 | 1.24 m | 3.23 s | |
| 0.65 | 0.55 | 0.60 | -0.24 | 2.47 m | 6.47 s | 几乎是直线，转不过弯 |
| 0.60 | 0.60 | 0.60 | 0.00 | ∞ | — | 完全不转 |
| 0.90 | 0.60 | 0.75 | — | — | — | **和=1.50 超红线，会被夹成 0.75/0.45** |

这十条都满足 `左+右 = 1.20`（正好卡在上限）。**想更慢通过弯道**就两个数一起减
（比如 `0.60/0.25` → v=0.425，半径 0.44 m），**想更急**就加大差值。

#### 怎么定值

赛道弯道半径实测是 **0.48~0.51 m**，两条独立参考数据都指向这里：

| 来源 | v | w | 半径 |
|---|---|---|---|
| 标准巡线参考曲线 | 0.18 | -0.35~-0.38 | 0.47~0.51 m |
| 原工程写死转弯 | 0.23 | -0.48 | 0.48 m |

所以默认取半径 ≈0.49 m（左 0.85 / 右 0.35）。

**右轮掉到 0 附近车就变成原地打转**——这是最容易踩的坑。程序会在实测速度
明显低于命令时打 `⚠ 转弯实测速度只有…` 告警，看到就把右轮调大一点。

**v 被红线卡死在 0.60，所以「半径够大」和「左轮顶格」只能二选一。**

### 入弯 / 出弯怎么调

判定在 `rush.py` 的 `_wait_turn_command()`（入弯）和 `_turn_command()`（出弯）里。

#### 入弯：纯里程，不看视觉

**改这一行（`rush.py` 第 632 行）：**

```python
RUSH_TURN_START_DISTANCE = 0.47   # 离桥基准点之后走这么多米就起转
```

`RUSH_TURN_TRIGGER` 固定用 `"odom"`。**为什么不用视觉**：2026-11-01 实车测出来
后桥段的 `entry=Y` 是**闪烁噪声**——过桥前就在零星出现，过桥后每 4 帧闪一次，
一解除封锁就凑够帧数触发，所以每次都在 0.27 m 同一个位置转，而且一旦不亮车就
永远不转、直接冲出赛道。

**里程的 0 点在哪**：过桥后按**固定 0.25 m** 稳车身（`BRIDGE_SETTLE_DISTANCE`），
走完那一刻就是基准点。每次启动日志和录像第三行的「桥后=X.XXm」都从这里算。

> 原来是靠 `BRIDGE_SETTLE_TIMEOUT = 2.5 秒` 超时放行的，而「车身平稳」判据用的
> 俯仰基线是上桥前在平地学的，过桥后俯仰停在 +7.9° 永远不满足——所以每次都跑满
> 2.5 秒，那段时间车在低速爬，**基准点会随速度漂**。改成按里程后 0 点就固定了。

**怎么量这个数**：跑一趟让它直冲出去，回放录像，找到车真正该起转的那一帧，
读画面第三行的「桥后=X.XXm」，填进来。日志也会打：

```
[标定] 本次起转点在离桥基准点后 0.470 m（RUSH_TURN_TRIGGER=odom，RUSH_TURN_START_DISTANCE=0.47）
```

#### 出弯：看视觉（王赛的逻辑）

**不再靠固定角度硬切**，改成「转到重新看见线、并且线回到画面中间就停」。

王赛原版 `shiwai.py::_has_left_foam()`：

```python
result.valid 且 left_line_rows >= 18 且 8 < left_edge_x < 0.42*画面宽
# 而且要盲转够 TURN_MIN_SPIN_SECONDS = 1.6 秒才认
```

他锁到「左侧海绵」后就不再盲转，改为顺着线走。我们右转出弯时的对应判据是
「新的一段线回到画面中间」，所以换成 `线有效 + 行数够 + |err| 小`：

| 常量 | 默认 | 作用 |
|---|---|---|
| `RUSH_TURN_LOCK_MIN_YAW_DEG` | 45.0 | 至少要转过这么多度才认视觉（= 王赛那 1.6 秒最小盲转） |
| `RUSH_TURN_LOCK_ERROR` | 0.18 | `|err|` 落在这范围内算「线回到中间」 |
| `RUSH_TURN_LOCK_ROWS` | 18 | 线的有效行数（王赛用的就是 18） |
| `RUSH_TURN_LOCK_FRAMES` | **4** | 连续这么多帧才算锁定（原来 2 帧=0.13s，高速扫过时线掠过画面中间就能凑够 = **假锁**） |
| `RUSH_TURN_YAW_DEG` | **180.0** | **角度上限**：视觉锁不到就按角度停（11-08 由 110 提到 180） |
| `RUSH_TURN_MAX_SECONDS` | 8.0 | 兜底超时 |
| `RUSH_TURN_EXIT_MODE` | `"vision"` | 出弯方式：`"vision"` 视觉优先 / `"angle"` 纯角度（跑基准用） |

**11-08 的重要修正**：原来是 2 帧（0.13 s）就算锁定，而转弯时相机以 69°/s 扫过，
线掠过画面中间就很容易凑够 2 帧 → 车会在任意角度**假锁**、提前停下。
现已收紧到 **4 帧**，并且出弯时把每一帧的证据全打出来（见下）。

优先级：**视觉锁定 > 角度上限 > 超时**。出弯时会打印是哪一种：

```
★ 出弯——视觉锁定（转过 78°，线回来了），转过 78.4°，用时 1.02s
★ 出弯——转够 110°（视觉没锁到，按角度兜底），转过 110.2°，用时 1.44s
```

看到第二条说明视觉没锁到，要么是 `RUSH_TURN_LOCK_ERROR` 太严，要么是
`RUSH_TURN_LOCK_MIN_YAW_DEG` 太大。

#### 一趟跑完，看这几行就知道出弯对不对

转弯只有 1~2 秒，1 Hz 状态行只采到 1~2 个点，所以**出弯时会把逐帧证据整段打出来**：

```
[标定-入弯] 直冲段 12 帧（0.80s），线有效 3 帧（线看得见，出弯判据可用）
[标定-出弯] 视觉锁定（转过 70°，线回来了） 转过=69.6° 用时=1.00s 帧=16 平均w=+1.21rad/s 退出方式=vision
[标定-出弯] 视觉统计：线有效 8/16 帧，最长连续 4 帧，|err|最小 +0.031
            （判据 行数>=18 且 |err|<=0.18 连续4帧）
[转弯帧] 00 d=   4.6° 线=- rows=  0 err=+0.000 锁定=0
[转弯帧] 01 d=   9.2° 线=Y rows= 21 err=+0.042 锁定=1
...
```

**怎么判断：**

| 看到什么 | 说明 | 下一步 |
|---|---|---|
| `[标定-入弯] …线有效 0 帧` | 入弯前根本没看到线 | 出弯判据不可能生效，只能靠 110° 兜底；要查相机/阈值 |
| `[标定-出弯] 视觉锁定…` 且 `最长连续 >= 4` | 视觉**真的**锁到了 | 看它锁在多少度：比 110° 小很多 = 提前出弯（可能是好事，也可能是假锁） |
| `[标定-出弯] …转够 110°（视觉没锁到…）` | 视觉一次都没凑够 4 帧 | 要么放宽 `RUSH_TURN_LOCK_ERROR`，要么本就该用纯角度 |
| `[转弯帧]` 里 `锁定=` 反复 0→1→0 | 线在闪，判据不稳定 | 放宽 `RUSH_TURN_LOCK_ERROR` 或 `RUSH_TURN_LOCK_ROWS` |

想先跑通全程、排除视觉这个变量，就把 `RUSH_TURN_EXIT_MODE` 改成 `"angle"`：
车会稳定地在 110° 停（这个值有数据支撑：王赛自己跑成功那趟反推是 **110.1°**）。

## 4. 首次上车必须标定三件事

1. **入弯触发距离 `RUSH_TURN_MIN_DISTANCE`** —— 最容易跑偏的一项。
   实测「视觉确认」在离桥后 **0.23~0.27 m** 就亮了，比弯道入口早，所以默认
   `0.00` 会**提前起转**。跑一趟，在录像里找到车真正该起转的那一帧，
   读画面上第三行的 `桥后=X.XXm`，填给 `RUSH_TURN_MIN_DISTANCE`。
   （详细步骤见第 3 节「入弯判定怎么调」）

2. **隧道盲冲时长** —— 看录像量「车头进隧道到车尾出隧道」的时间，
   再留 0.3~0.5 秒余量填给 `RUSH_TUNNEL_SECONDS`。
   早起身会撞隧道顶（而且规则要罚「未起身」），晚起身只是慢一点，宁晚勿早。

3. **右转弯的左右轮速度** —— `RUSH_TURN_LEFT` / `RUSH_TURN_RIGHT`，
   按第 3 节那张表，看车是转不够还是转过头。

## 5. 已知风险（照优先级）

1. **直冲段只靠固件保航向**。`w=0` 时固件会锁住「w 归零那一刻」的朝向，
   所以**起步必须自己把车摆正**；车头偏几度，直冲几米后就会偏出去。
   如果录像里发现明显跑偏，两个选择：改用 `RUSH_TURN_TRIGGER="odom"`（不依赖
   视觉，但也不修正横向偏差），或者在 `_rush_command` 里加一段 IMU 航向微调。

### 已修的坑（11-01 19:37 实车）

**症状**：入弯时车**原地打转**，不沿弧线过弯；IMU 却报「转过 90°」，
程序以为转完了直接进停车段。日志里这一行是关键证据：

```
[RUSH] TURN  v=+0.37 w=-2.43 → 左轮=+0.87 右轮=-0.13
```

**原因**：`右轮 = v + w*半轮距 = 0.37 − 0.50 = −0.13`，**右轮在倒转**。
v 只有 0.37 而不是 0.60，是因为过桥收尾那段 `BRIDGE_SETTLE_SPEED = 0.10` 把速度
压得很低，而入弯触发**常常在离桥后十几厘米就响**（这趟 0.18 m），此时 v 还在以
0.25 m/s² 往上爬。转弯本身只持续 0.9 秒，v 根本来不及回到 0.60。

**修法**：加「起转前先把前进速度拉到位」的门控。v 没到 `RUSH_TURN_V − 0.05` 之前
只直着加速、不旋转、也不计 yaw 和用时（`_turn_start_yaw` / `_turn_started_at`
每帧重置），拉速度期间用 0.60 m/s²（原工程桥区同值）。而且这个加速**从离桥那一刻
（`MODE_WAIT_TURN`）就生效**，不是等入弯触发才开始，少直冲约 0.2 m。带确定性回归测试：

| | 起转时 v | 转弯中右轮最小 | 起转前直冲 | 结果 |
|---|---|---|---|---|
| 旧逻辑 | 0.12 | **−0.34** | 0.01 m | 右轮倒转 → 原地打转 |
| 新逻辑 | 0.60 | **+0.10** | 0.29 m | 右轮始终正转 → 沿弧线过弯 |

**代价**：起转前要多直冲约 **0.29 m**，转弯总耗时从 1.07 s 变成 1.87 s。
如果发现冲过头、入弯点偏晚，调小 `RUSH_TURN_V_READY_TOL`（比如 0.12）可以让它
早点起转，但右轮会接近 0 甚至轻微倒转。

### 已修的坑（11-01 19:45 实车）

**症状**：车过完桥、正要入弯时**直接停死**，一路 `v=+0.00` 直到手动 `Ctrl+C`。
日志：

```
bridge=exit_hold  v=+0.20  pitch=+6.8 → +9.8 → +10.4
>>> 过桥异常停车（未判定过桥）：body level/clearance still unconfirmed after exit hold
bridge=fault      v=+0.00   → 卡在 dist=2.83m
```

注意：**这趟根本没走到转弯**，不是转弯逻辑的问题——是过桥收尾判故障把车停了。

**原因**：过桥收尾要等「车身回平」，判据是俯仰差 `dp <= BRIDGE_EXIT_PITCH_DEG(5.0°)`，
而且这个差值是**相对起步时学到的基线**算的。把最近三趟的俯仰序列并排看：

| 趟次 | 起步基线 pitch | 过桥后 pitch | dp | 结果 |
|---|---|---|---|---|
| 19:37 | **+8.9**（停在坡上学的） | +7.7 | −1.2° ✓ | 确认离桥 |
| 19:45 | **−1.6**（停在平地上学的） | +7.9 | **+9.5°** ✗ | 3 秒后故障停车 |

**两次过桥后车身俯仰一模一样（+7.7 / +7.9）**，唯一差别是起步时那条基线差了 10°。
基线在平地上学时，过桥后的 dp 永远 ≈ +9.5° > 5.0°，`good` 永远不成立，
`exit_hold` 滚行 3 秒后必然 `fail` → 节点停车 → 整趟报废。

**修法**：加 `RUSH_BRIDGE_RESCUE` 兜底。判故障时看三个条件——横滚已回到基线 4° 内
（桥上时是 −12.5°）、进桥后已走 ≥1.00 m、俯仰差 ≤15°（防翻车）——满足就
**记一条警告、按「已离桥」继续跑**，而不是停死。理由很直接：这里停死 = 整趟没成绩，
带几度俯仰不确定继续跑明显更划算。四个「不该救」的边界都有回归测试：
横滚还在 −8°（像还在桥上）、只走了 0.50 m、俯仰差 20°、别的故障原因（传感器断了）
——**一律不救**。

**代价**：救回来后仍要走完 `BRIDGE_SETTLE_TIMEOUT = 2.50 秒` 的低速滚行
（`BRIDGE_SETTLE_SPEED = 0.10`），再进 `WAIT_TURN`。这也正是上面第二条那个
「入弯时 v 上不来」的来源，两条已经互相接上了。

**现象**：转弯和停住都很漂亮，但停住之后车身前后点头，还会往回倒。

**对照实验**（三趟录像，出弯后的 `ov` 序列）：

|---|---|---|
| 103637 | 旧软刹 0.75 | +0.57 +0.57 +0.59 +0.59 +0.60 +0.60 +0.04 +0.04 → **平滑，不点头** |

4.45 → 3.94 → 4.44 的 0.6 m 来回 —— 是**前后点头（hobby-horsing）**，

| 0.75（旧） | 0.80 s | 0.24 m | 无，但冲太远 |
| **1.50（现在）** | **0.40 s** | **0.12 m** | 明显减轻 |
| 3.00 | 0.20 s | 0.06 m | 最厉害，会往后倒 |

停住后给一点与实测后退速度反向的小速度按住它。注意底盘启动阈值 ≈0.18，
`RUSH_SIDEWALK_HOLD_MAX` 不要给太小，否则推不动。

### 已修的坑（11-08 11:01 · 停不住，一直往后倒）

**现象**：停车位置很准，但停不住，停完还往后溜。

**先挖出的一个真 bug**：`BridgeTraversal.odom()`

```python
self.distance += max(0.0, 0.5 * (self.speed + speed)) * dt
#                 ^^^^^^^ 负速度被夹成 0
```

**`dist` 是个棘轮，只增不减。** 车往后倒的时候它不但不降，还因为别的抖动继续涨
（11:01 那趟 `dist` 从 3.95 涨到 4.84，而 `ov` 同时报 −0.28）。
**这就是为什么前面三次我都判成"没后退"** —— 看 `dist` 是看不出来的，
只有 `ov`（瞬时速度）才说实话。

**根因**：出弯后只发 `v=0`，底盘不会主动锁住位置，车自己往后溜。

**改法**：加**停车位置保持**。
1. 桥里新增 `signed_distance`（不夹负号的真·带符号里程）
2. `_enter_sidewalk` 把那一刻的 `signed_distance` 记成目标点
3. 之后每周期算偏差 `drift = 目标点 − 当前`（正 = 往后跑了），按 `增益 × drift`
   给一点往前的速度把它拉回来

| 增益 | 稳态偏差（溜 0.28 m/s 时） |
|---|---|
| 0（关） | 一直溜，6 秒退 1.68 m |
| 1.5 | 0.19 m |
| **3.0（现在）** | **0.09 m** |
| 5.0 | 0.06 m |
| 8.0 | 0.04 m |

> **纯比例控制一定有稳态偏差** = 溜的速度 ÷ 增益。想让偏差更小就把
> `RUSH_SIDEWALK_HOLD_GAIN`（第 761 行）调大；太大可能会来回窜。

HUD 里现在能直接看到：`位置偏差=+0.093m  保持v=+0.28`。

### 已修的坑（11-01 20:16 实车）

**修法**：
1. **把 `install` 里的 `rush.py` 改成指向 `src` 的软链接**（只动这一个文件）。
   以后改 `src` 立即生效，不用编译。没有用 `colcon build --symlink-install`，
   因为那会连带把王赛的文件也换成软链接——他的 src/install 本来就不一致，
   等于悄悄改掉他实际跑的版本。
2. 加了**开机自检** `_check_stale_install_copy()`：启动时先判断是不是软链接；
   不是就比对两份文件的 10 个关键参数，不一致就把「src 里是多少、实际生效是多少」
   并排打出来。
3. 加了 `~/wheel_robot/rush_symlink.sh`，`colcon build` 覆盖掉软链接后跑一下即可恢复。
4. 启动横幅新增「入弯触发：visual，离桥后至少 X.XX m 且视觉确认才起转」，
   每次开机一眼看到实际生效的门槛。

**教训**：以后改完参数先看启动输出的「入弯触发」那行和有没有 `⚠⚠⚠`。

## 6. 看录像量速度

录像在 `~/wheel_robot/recordings/rush_日期_时间.avi`，同时有 `rush_latest.avi` 软链接。
HUD 第二行的字段顺序和原工程完全一致，所以原来的工具能直接用，**但 w 量程要调大**：

```bash
cd ~/wheel_robot
python3 src/wheel_robot/tools/hud_vw_series.py recordings/rush_latest.avi \
    --csv /tmp/rush_vw.csv --plot /tmp/rush_vw.png \
    --w-max 2.5 --w-limit 2.43
```
CSV 列：`t, frame, v, w, ov, v_score, w_score`（`ov` 是实测速度）。

不用这个参数的默认值（±0.60）会把转弯段的 w 削平。

**两个读数的坑，分析时要注意**：

- `ov` 为负时工具量不出来。HUD 上 `ov=-0.14` 比样本 `ov=0.00` 多一个字符，
  后面所有字段（含 `w`）整体右移一格，`w` 就会读成 0.04~0.60 的随机值。
  判断方法：看 `w_score`，正常 0.99，错位时掉到 0.86。
  **车停住那段的 `w` 读数不可信**，实际是 0.00（`v=0.00` 时本来就不发角速度）。
- 所以分析静止段只看 `v` 和日志，别拿录像里的 `w` 说事。

- `v/w` = 实际发出的指令，`ov` = 实测速度，`左轮/右轮` = 由指令反算的轮速
